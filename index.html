Testing is a lifecycle. Four stages: test design, test automation, test execution and test management.
Today, most of the activities in each stage are still manual or rule-based. Evaluating requirements. Writing test cases. Provisioning data. Writing reports.
Agents can take the heavy lifting in every stage. Not to replace testers, but to amplify them.

One new record in. Tested requirements out.

This is the first agent, the Requirement Analyst. It takes one input, the requirement text. It returns two outputs: an integer Score from zero to a hundred, and a Reasoning string explaining why.
It's built to answer one question: could a test generation agent create meaningful positive and negative test cases from this, without asking follow-up questions? If yes, the score is high. If not, it's low.

Once the requirement is approved, or was clear enough to begin with, Maestro creates it in Test Manager and gets back its ID. That ID goes to the second agent, together with the requirement text.
This agent has a clear persona: a senior QA test designer. It uses equivalence partitioning, boundary value analysis, decision tables and state transition analysis. It covers positive, negative, boundary and edge scenarios.
Notice the output. It never returns free text. It returns structured JSON. Name and description. Properties, like test type and priority. Test steps, each one a verb-first action with an observable expected result. And a summary with coverage notes and assumptions.
It has to ground everything in the requirement and not invent functionality. Any open question goes into the assumptions. And if nothing testable can be derived, it returns an empty list, and still returns a complete summary. It says "I can't" rather than making something up.

Before we run it, four choices you can reuse in your own flows.
Event-driven. A new record starts the work. Nobody has to remember to run anything.
One agent, one job. Scoring and generation are separate agents. Each has a narrow brief, its own evaluation set, and can use a model suited to the job. That makes each one easy to test and improve.
Human only when needed. Judgement is requested exactly where the score says it is needed, and nowhere else.
And traceable and resilient. The requirement and its test cases are linked in Test Manager, and every failure sends an email.
